3. 핵심 동작 흐름 (Flow)
    ① Forward vs Redirect 흐름
        Forward (포워드):
            브라우저의 요청이 들어오면 서버 내부에서 다른 서블릿이나 뷰로 제어권을 넘김.
            브라우저는 이 내부 이동을 알지 못하므로 URL 주소창이 변하지 않으며,
            최초 요청 시 생성된 HttpServletRequest 객체가 유지됨.
            (요청 횟수: 1회)
        Redirect (리다이렉트):
            컨트롤러가 redirect:/를 반환하면 ViewResolver 대신 RedirectView가 개입하여
            브라우저에게 HTTP 302 Found 응답과 함께 새로운 이동 경로(Location 헤더)를 보냄.
            브라우저는 해당 주소로 새로운 GET 요청을 보내므로 URL 주소창이 변경되고 기존 Request 객체는 소멸.
            (요청 횟수: 2회)

    ② 세션 기반 로그인 인증 흐름
        사용자가 loginForm.html을 통해 로그인 정보를 제출.
        서버(HttpSession)는 사용자 인증 성공 시 고유한 세션 ID(JSESSIONID)를 생성하고, 관련 유저 데이터를 서버 메모리에 저장.
        생성된 세션 ID는 HTTP 응답 헤더를 통해 브라우저의 쿠키(세션 쿠키)에 저장.
        이후 브라우저가 다시 요청을 보낼 때마다 쿠키에 담긴 세션 ID가 자동으로 서버에 전송되며,
        서버는 이 ID를 조회하여 로그인 상태를 식별.

4. 실습 포인트
    - 데이터 유실 방지 및 중복 방지:
        단순 조회 화면은 Forward를 사용하지만,
        등록/수정/삭제와 같은 상태 변경 작업 후에는 새로고침으로 인한 중복 요청을 방지하기 위해
        반드시 Redirect(PRG 패턴: Post-Redirect-Get)를 적용해야 함을 인지.
    - 적재적소의 저장소 활용:
        보안이 중요하고 서버에서 관리해야 하는 정보(예: 로그인 세션)           → Session
        HTTP 요청마다 서버로 자동 전송되어야 하는 식별자나 보안과 무관한 설정   → Cookie
        서버에 부담을 주지 않고 브라우저에만 유지할 UI 상태나 단순 임시 저장    → Web Storage



** 알아두기 **
1. redirect:/
    - 서버가 브라우저에게 “다른 주소로 다시 요청하라”고 명령하는 동작.
    - 브라우저는 서버가 알려준 새로운 URL로 자동으로 새 요청을 보내며, 그 결과 브라우저 주소창(URL)이 새로운 경로로 변경됨
    - 중복 실행 방지(새로고침을 누를때마다 기능에 대한 반복 요청 방지)


2. @RequestParam 핵심 정리
    개념:
        HTTP 요청 URL의 쿼리 스트링 파라미터를 자바 매개변수에 자동으로 매핑해주는 어노테이션.
    주요 속성:
        name (또는 value): 요청 파라미터의 key 이름과 매개변수명을 매핑.
        required: 필수 여부를 지정하며, true(기본값)일 때 해당 파라미터가 없으면 400 Bad Request 에러가 발생.
        defaultValue: 파라미터 값이 비어있거나 없을 때 기본으로 적용할 값을 설정.


3. Validation 핵심 정리
    a. 에러의 종류
       - 필드 에러(Field Error) : 특정 "필드(입력값)"에 대한 유효성 검증 실패 시 발생.
                                에러 정보는 BindingResult 객체에 자동으로 저장됨.

    b. 주요 검증 어노테이션 종류
       @Size(min=, max=) : 문자열의 길이 또는 컬렉션의 크기 제한
       @NotNull          : null값만 허용하지 않음 (빈 문자열 "" 이나 공백 " "은 통과됨)
       @NotEmpty         : null과 빈 문자열("") 불가 (공백 " "은 통과됨)
       @NotBlank         : null, "", " " 모두 불가 (문자열 검증 시 가장 안전하고 자주 사용)
       @Past             : 과거 날짜만 가능 (현재 날짜 제외)
       @PastOrPresent    : 오늘을 포함한 과거 날짜만 가능
       @Future           : 미래 날짜만 가능 (현재 날짜 제외)
       @Max(value=)      : 숫자의 최댓값 제한
       @Min(value=)      : 숫자의 최솟값 제한
       @Pattern(regexp=) : 정규표현식을 이용한 문자열 패턴 검사
       @Valid / @Validated : 컨트롤러 매개변수나 하위 객체(Object)의 Validation을 실제 구동시킴

    c. 자주 사용하는 정규식 예시 (Java 코드 작성 기준 - 역슬래시 2개 필수, 탈출문자 문제)
       목적                  정규식(regexp)                 				설명
       -------------------------------------------------------------------------------------------------
       한글만                 "^[가-힣]+$"                  				한글만 허용 (공백 불가)
       영어만                 "^[a-zA-Z]+$"                 				영문자만 허용
       숫자만                 "^[0-9]+$"                    				숫자만 허용
       영문자+숫자            "^[a-zA-Z0-9]+$"              				영어와 숫자 조합 허용
       전화번호 (하이픈 없이)   "^010\\d{3,4}\\d{4}$"         				예: 01012345678 (3,4자리 호환)
       전화번호 (하이픈 포함)   "^010-\\d{3,4}-\\d{4}$"       				예: 010-1234-5678 (3,4자리 호환)
       이메일                 "^[\\w.%+-]+@[\\w.-]+\\.[a-zA-Z]{2,6}$" 	일반적인 이메일 형식
       주민등록번호            "^\\d{6}-\\d{7}$"             				앞 6자리 - 뒤 7자리 형식


4. 저장소 기술 비교 (Cookie / Session / Web Storage)

💡 HTTP는 무상태(stateless) 프로토콜이기 때문에, 요청이 끝나면 "누가 요청했는지", "이전에 어떤 상태였는지" 서버는 기억 못함.
    - 사용자 상태를 유지하기 위해 Cookie, Session, Web Storage를 배움
